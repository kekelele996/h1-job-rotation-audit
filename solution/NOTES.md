# 参考解说明

## 三个难点

| 编号 | 错误认知 | 正确知识 | 可观察行为 | 对应测试（tests/scoring.json） |
|---|---|---|---|---|
| difficulty_1（判定） | 一个长 L 的圈执行 k 次会拆成 k 份，所以每种长度的圈数必须是 k 的整数倍；记录仪坐标就是真实坐标 | 拆出的份数是 `gcd(L, k)`；同长 m 圈能拼回长圈要组大小 `g` 满足 `g | k`、`gcd(k/g, m) = 1`、`m·g > k`；记录仪零点未知，要对每个零点把记录转回真实坐标再判 | 两个方向都错：`k=4` 时四个不动点被判"有解"；`k=6` 两个 4 圈、`k=9` 三个 4 圈被判"无解" | `test_rejects_table_where_nobody_rotates`、`test_accepts_two_four_cycles_at_six_rounds`、`test_accepts_three_four_cycles_at_nine_rounds` |
| difficulty_2（计数） | 只能把每 k 个同长圈并成一个；每个零点各算一遍再加起来 | 一组 g 个同长圈的排法是 `(g-1)!·m^(g-1)`；同一长度可能同时允许几种组大小；不同零点解释出的表会重叠，张数是**并集**大小 | 三个计分样例是 128、12、54；按零点相加会得到 384、24、162 | `test_counts_three_four_cycles_at_nine_rounds`、`test_counts_two_three_cycles_at_two_rounds`、`test_counts_three_three_cycles_at_three_rounds` |
| difficulty_3（总路程） | 给出一张能解释 0 号零点的表就行，报它的路程 | 总路程按组可加，但最小要在**并集**上取：不同零点的解集不同，最省的往往不是 0 号零点解出来的那张 | 报出的最小总路程偏大（S-01 报 10，人工结论是 6） | `test_cost_for_two_three_cycles_at_two_rounds`、`test_cost_for_three_three_cycles_at_three_rounds`、`test_cost_for_four_three_cycles_at_two_rounds` |

三个难点分别落在 `exists_root`、`count_roots`、`build_root`/`min_cost` 上，留一法按函数名退回镜像里的原写法；实测只修一个时得分 0.67 / 0.67 / 0.66，全修 1.000。

## 关键步骤

1. 对每个零点偏移 o，把记录转回真实坐标：`target_o(p) = (after[(p+o) % n] - o) % n`。
2. 对 `target_o` 做圈分解，算出每种长度允许的组大小：`g | rounds`、`gcd(rounds/g, length) = 1`、`length·g > rounds`（最后一条来自内控口径）。
3. 同一长度内按组大小做背包计数：`ways[t] = Σ C(t, g·j)·ways[t-g·j]·W(g,j)`，其中 `W(g,j) = (g·j)!/((g!)^j·j!)·((g-1)!·length^(g-1))^j`。
4. 所有零点、所有长度的解取并集；并集大小是 `root_count`，并集里的最小总路程是 `min_cost`。
5. 构造：组内用 `inv = (rounds/g)^(-1) mod length` 把各圈交错摆进长圈，再沿长圈走一格定义 `root`；并集里取总路程最小的那张。

## 核心公式与独立复算

- 圈拆分：长 `L` 的圈执行 `k` 次，拆成 `gcd(L, k)` 个长 `L/gcd(L,k)` 的圈。
- 组内排法：`(g-1)! · m^(g-1)`；分组方案数：`(g·j)! / ((g!)^j · j!)`。
- 判定条件：`g | k` 且 `gcd(k/g, m) = 1` 且 `m·g > k`。
- 零点：`target_o = c_o⁻¹ ∘ after ∘ c_o`；并集 `∪_o { ρ : ρ^k = target_o }`。

两条独立路径：

- 穷举路径：`research/prototype.py` 枚举 `n ≤ 8` 全部置换与全部根，369864 组差异 0；`research/scratch/v3_union.py` 按零点枚举并取并集，与参考解逐个一致。
- 解析路径：`research/verify_counts.py` 用个数向量重算各长度方案数；`research/scratch/enumerate_min.py` 枚举全部分组与摆法，去重后的表数与计数公式一致。

## 容差依据

计数、判定和总路程都是整数，判据是精确相等，没有数值容差。唯一的精度风险是"用浮点算组合数"，所以题面写明不能用浮点近似，参考解全程用 `int`。

## 边界与幂等

- 边界：`k = 1` 时每个圈长都要大于 1，对照表不能有不动点；`k` 不小于岗位数时一定无解；岗位数不超过 12（题面写明），参考解对每个零点枚举全部合规表，规模可控。
- 幂等：同一份对照表重复执行，两次输出一致（按圈长升序、固定分组顺序，最后按总路程与字典序取最小，没有随机性）。

## 权重依据

- 判定占 0.33：判定错了后面三个字段都无从谈起。
- 计数占 0.33：业务上要回答"一共有几张"，漏掉一种组大小或把并集算成相加都会错。
- 总路程占 0.34：人手紧时选哪套排法直接决定交接工作量；它要在并集上取最小，和计数不是同一套推理。
- 三个难点内部三个测试接近均分，让"只修一半"的写法也能被区分开。
